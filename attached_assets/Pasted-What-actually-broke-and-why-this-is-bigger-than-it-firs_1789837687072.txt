What actually broke, and why this is bigger than it first looked
The first pass on the release report flagged two broken things in artifacts/api-server/src/routes/invoices.ts. Digging further to write this fix confirmed the damage is more extensive: one commit corrupted six different things in this one file, all consistent with a bad merge (the commit itself carries a Replit-Merge-Attempt trailer) that shifted several function bodies down by one position, so each function's real ending got welded onto the next function, cascading through the whole file:
POST /invoices (create a new invoice) — completely broken. References variables (invoicePatch, acceptedLineItems, result) that don't exist in this handler, uses the wrong body schema, and never actually inserts a row. First request throws.
GET /invoices/:id (fetch a single invoice) — the route is gone entirely. Its body got relabeled and squatted under POST /invoices/:id/decision instead (see #4). Any page that loads one invoice by ID will 404.
PATCH /invoices/:id (edit an invoice) — completely broken. Ends by reading result.deleted from a result that's never declared in this handler. The real update transaction (participant-link revalidation, the actual UPDATE, replacing line items) is gone. First edit throws.
POST /invoices/:id/decision (approve/reject) is registered twice, and both copies are wrong:
The first registration (the one Express will actually use) is really GET /invoices/:id's body relocated here — it silently fetches and returns the invoice unchanged. Staff clicking Approve or Reject will get a 200 response and see no error, but the invoice's status never changes.
The second registration (dead code — unreachable because of the duplicate above) still has its real approve/reject logic, but its transaction body was replaced with a call to softDeleteInvoice(...) — even if it were reachable, it would soft-delete the invoice instead of approving it, and it drops the check that blocks approval when a line's authorization is exhausted/expired.
The two invoice queue endpoints are deleted outright: GET /invoices/queues/ready-to-approve and GET /invoices/queues/ready-for-check-writing no longer exist as routes at all, even though the OpenAPI spec, the generated client, and pages/invoices.tsx all still call them. The invoiceQueue() helper function is still defined but nothing calls it anymore. Two of the three invoice-workflow queues (Marie's approve queue, the check-writer's queue) will 404 in the UI right now.
POST /invoices/:id/validate — the two authId bugs already reported (bare, undeclared authId used in the "authorization active" and "service month in period" checks instead of item.authorizationId).
Net effect right now: creating an invoice, editing one, fetching one directly, approving/rejecting one, and viewing the approve/check-writing queues are all broken. Only the invoice list (GET /invoices) and delete (DELETE /invoices/:id) still work correctly — and the list's own search-query improvements from that same commit are fine and should be kept.
